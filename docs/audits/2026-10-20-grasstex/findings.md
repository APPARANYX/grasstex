# Evidence register — defects, workarounds, architecture risks

**Reading rule:** A confirmed **source-level** property is not automatically a reproduced battle failure. Every finding below identifies which evidence exists, what remains unverified, root cause, target correction, effort/risk and validation gates. References are frozen at the audited SHA `f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9`.

## A — Immediate correctness, security and integrity

### SEC-01 — Policy and scenario-learning writes lack caller authentication
- **Severity/category:** **High / Security**. **Status:** confirmed source-level missing caller-authentication check; direct externally exploitable behavior not tested. **Confidence:** high for inspected PHP; medium for deployed perimeter (unseen host controls could add authorization).
- **Source:** [`battle_policy.php:70–90`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle_policy.php#L70-L90) and [`battle_learning.php:136–201`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle_learning.php#L136-L201). Both accept POST using only `HTTP_ORIGIN` parsed host equal to `test.ivandpopov.com`; no secret, bearer key or authenticated session appears along those write paths. `battle_policy.php` additionally accepts a supplied `baseRevision` read from public GET. Contrast with [`wargame/api.php:28–51`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/wargame/api.php#L28-L51) which validates role and administrator keys, and [`labs/save-calibration.php:18–35`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/labs/save-calibration.php#L18-L35).
- **Root cause:** an Origin check (useful anti-CSRF defense) is treated as authentication for persistent state changes. An HTTP client may set its own Origin.
- **Effect:** untrusted policy/learning records may be written by an unauthorized caller if the host exposes these PHP paths. The genome currently being stashed client-side does **not** deactivate the PHP write endpoint.
- **Fix:** server-side disable these writes if unused; otherwise require secret-based authorization/identity and use Origin/CSRF controls only as additional protections. Keep legitimate training access separately scoped. Audit filesystem and backup existing state before any deployment.
- **Migration risk:** Medium (could break legacy trainer workflow); **verification:** unauthenticated valid POST → 401/403 without state change; authorized POST → validated update; negative tests for forged Origin; disabled route returns non-200. No probing of deployed endpoint was performed.

### PHY-01 — Dynamic trucks block sight and ballistic rays but not infantry/transport navigation
- **Severity/category:** **High / Correctness + Architecture**. **Status:** **confirmed interface mismatch**, precise live player symptoms not reproduced; **confidence high**.
- **Source:** [`58-strategic-abstract-transport.js:307–369`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/modules/58-strategic-abstract-transport.js#L307-L369) publishes truck OBBs to `sim.obstacles.__dynamicFootprints` **only with `?truckCollision=1`**. [`battle-navigation.js:107–129`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/battle-navigation.js#L107-L129) defines `movementClear(a,b)` as intersection against module-local static `walls`, with **no dynamic footprint argument or query**. [`58...:44–55`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/modules/58-strategic-abstract-transport.js#L44-L55) passes a third `{ignoreDynamicId:vehicleId}` parameter to that two-argument function (ignored). [`obstacle-field.js:303–336`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/obstacle-field.js#L303-L336) explicitly adds dynamic footprints to sight queries; [`14-z-ballistic-raycast.js:211–278`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/modules/14-z-ballistic-raycast.js#L211-L278) propagates them to projectile obstruction checks. [`battle-sim.js:800–835`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/battle-sim.js#L800-L835) performs its final physical-step wall check with `movementClear`.
- **Root cause:** static navigation wall topology and dynamic volumetric obstruction live in different query services, with no common movement contract.
- **Effect:** the same vehicle can occlude shots/sight while offering no authoritative movement collision. With the flag off it is absent from dynamic obstacle queries altogether. The extent of existing supplementary avoidance or collision mechanisms elsewhere needs an actual integrated test.
- **Correction:** add one authoritative world-geometry query API with named `move`, `sight`, `shot` modes and explicit self-exclusion. Dynamic truck OBBs must be registered by simulation ownership, not by mesh load; use geometry uniformly for foot movement, transport paths and projectiles.
- **Risk:** High (routes, doorway/portal tolerance, boarding must permit intended self-overlap); **tests:** stationary/moving OBB, infantry blocked, intended driver/player door access allowed, shots stop at OBB and contact resumes correctly; replay same seeds old/new; do not simply turn on collision without compatibility and throughput checks.

### BALL-01 — Obstruction-query failures can fail open
- **Severity/category:** **Medium / Correctness**. **Status:** confirmed code behavior under thrown exceptions, no observed throwing production input. **Confidence:** high code / low occurrence.
- **Source:** [`14-z-ballistic-raycast.js:271–287`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/modules/14-z-ballistic-raycast.js#L271-L287): catches and silently ignores exceptions from obstacle field and navigation ray checks, then returns `false` (unblocked) if no successful blocker result.
- **Root cause:** a silent fallback hides broken geometry contracts and treats unknown as passable.
- **Correction:** record structured diagnostic error and deterministic fail-safe decision when geometry query cannot establish a valid result; keep normal support for intentional visibility windows.
- **Risk:** Medium (fail-closed policy could stop shots in exceptional geometry cases); **tests:** inject throwing geometry services and verify no falsely clear shot, bounded error counter, deterministic replay; verify normal no-blocker rays remain clear.

- **Risk:** Low–Medium (changing advertised QA flags can affect hosted test behavior); **tests:** execute launcher redirect, assert all requested keys survive, inspect effective feature values, compare direct staged mode.

### TRN-01 — Transport dismount can wait indefinitely on a blocked exit
- **Severity/category:** **Medium / Correctness + Liveness**. **Status:** missing fallback/timeout branch confirmed, permanent blockage not reproduced. **Confidence:** high for local control flow.
- **Source:** [`58...:829–845`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/modules/58-strategic-abstract-transport.js#L829-L845) rejects exit if any live nearby non-passenger is inside body width. [`58...:846–892`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/modules/58-strategic-abstract-transport.js#L846-L892) increments `exitBlockedAt`, logs once, and returns forever until `exitSpaceFree`; no timeout or reroute branch. [`58...:1218–1265`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/modules/58-strategic-abstract-transport.js#L1218-L1265) dispatches disembarking directly before re-evaluating normal mission cancellation.
- **Root cause:** release liveness delegated implicitly to environmental clearance without a terminal recovery guarantee.
- **Correction:** first reproduce sustained exit obstruction using a frozen blocker; then choose deterministic alternate door, safe accessible reposition of blocker, or explicit recoverable abort. Do **not** teleport occupants through collision.
- **Risk:** Medium; **tests:** permanently blocked primary door, both doors blocked, blocker death, restart while blocked, death of exiting passenger, no orphan seat or vehicle reservation. Preserve one-seat-per-simulation-step rule and continuous world positions.

### HOOK-01 — Module-hook error isolation can hide partial lifecycle failure
- **Severity/category:** **Medium / Correctness + Diagnostics**. **Status:** confirmed error semantics; no current broken hook identified. **Confidence:** high.
- **Source:** [`module-registry.js:115–142`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/module-registry.js#L115-L142): all hook exceptions are logged and swallowed for continuation, including `onBattleStart` and `onBattleRestart`.
- **Root cause:** a failure-containment policy appropriate for optional observers is applied to critical world-state mutation too.
- **Correction:** register hook criticality; fail initialization/restart atomically when authoritative services cannot reestablish invariants, while allowing optional UI/telemetry observers to fail nonfatally; attach structured failure to diagnostics.
- **Risk:** Medium; **tests:** inject failed essential transport/objective reset and assert no playable half-reset; inject failed optional overlay and assert simulation remains functional with error disclosed.

### PHASE-01 — Eleven fully connected squad phase labels do not restrict legal transitions
- **Severity/category:** **Medium / Complexity**. **Status:** confirmed design property, **not a bug**. **Confidence:** high.
- **Source:** [`16-squad-plan-stability.js:842–945`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/modules/16-squad-plan-stability.js#L842-L945): 11 phases, `next: PHASE_NAMES.slice()` for every phase; `transitionPhase` enforces only membership and permitted entry-type. The source explicitly says replacement missions can enter any phase.
- **Root cause:** the phase table describes execution modes rather than encoding transition guards.
- **Correction:** evaluate whether `commandPhase` is best treated as a discriminant of mission execution (with mission version/guard checked elsewhere) and whether labels such as `approach` vs `clear-town` can be derived. Keep **orthogonal** `sq.state` for combat status, not a product FSM of all combinations.
- **Benefit:** potentially smaller branch/state space and easier legality proof; **risk:** high if prematurely removing phases used for leases, UI, scoring. **Tests:** transition-table + role/mission interruption, compare outputs and objective closure over exact-seed paired benchmark.
- **Metric:** 11 names with up to 110 non-self directed adjacency entries; this does **not** imply 110 valid contextual behaviors or 110 buggy transitions.

### CLOCK-01 — Multiple cadences and simulation/live clock modes complicate reproducibility
- **Severity/category:** **Medium / Architecture + Testing**. **Status:** implementation complexity, nondeterminism not demonstrated. **Confidence:** high.
- **Source:** [`battle-sim.js:859–884`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/battle-sim.js#L859-L884) moves per render dt and updates AI via a 0.15-s accumulator; [`commander-ai.js:797–811`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/commander-ai.js#L797-L811) adds a second render observer for 0.45-s Macro command; [`00-fixed-step-clock.js:38–64`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/modules/00-fixed-step-clock.js#L38-L64) has optional explicit 0.15-s stepping and a cap of 12 catch-up iterations.

### ROUTE-01 — Steering and path correction use multiple implicit recovery mechanisms
- **Severity/category:** **Low–Medium / Complexity and potential performance**. **Status:** source-observed nested corrections; true duplication/unnecessary layers not established. **Confidence:** medium.
- **Source:** [`battle-sim.js:768–835`](https://github.com/APPARANYX/grasstex/blob/f89939f2f6e8ff21063d1b24c28a8ab73fe9d2e9/battle/battle-sim.js#L768-L835): steer-around, preserve navigation leg, retry plain heading, physical resolveStep, invalidate-nav-cache under `NAV_REPLAN_HOLD`. - **Root cause hypothesis:** scenario-by-scenario fixes may have split path selection and legal integration correction.

- **Risk:** Medium; **tests:** corner/door/hedge/ruck, path oscillation, progress to squad mission (not just nearest waypoint). Do not delete safeguards by inspection alone.

## Register closure rules

Every proposed fix should capture: (1) exact seed + URL + flags; (2) initial and terminal snapshots; (3) before/after invariant counts; (4) old/new measurable trajectory or benchmark outputs; (5) unchanged control runs; (6) profiling overhead where applicable. Turn confirmed source-level contracts into executable tests before altering AI or physics.
